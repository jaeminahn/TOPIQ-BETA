폴링의 반대 근거: 언마운트 시 타이머는 해제되고 듣기 편집 중에는 멈춥니다. 부모 폴링도 작업이 있을 때만 동작합니다. 그래도 유휴 세트 조회와 부모/자식 중복 비용은 남습니다.
로고 크기는 파일에서 확인했으며, 실제 HTTP 압축·캐시 적중 여부는 확인하지 않았습니다.
기존 dist는 최신성을 보증할 수 없어 현재 배포 번들 크기로 사용하지 않았습니다.

## 검증 방법

1. 실제 데이터량과 유사한 격리 DB에서 마라톤 후보 쿼리의 EXPLAIN (ANALYZE, BUFFERS), 행 수, DB 시간과 pool 대기시간을 비교합니다.
2. 관리자 듣기 화면을 유휴/생성 중/숨긴 탭 상태로 열어 1분간 요청 수와 중복 요청 수를 비교합니다.
3. 새 production build에서 초기 JS 청크·gzip/Brotli 크기, 첫 방문 logo 전송량 및 LCP를 비교합니다.
4. 50문항 제출 쿼리 수와 p95 제출 지연을 비교하고 동시 제출의 멱등성을 검증합니다.
5. 느리거나 실패하는 Storage/Google 응답을 테스트 대역으로 주입해 연결 반납, 취소, 작업 재개를 확인합니다.

현재 검토에서 기능 코드나 운영 설정은 수정하지 않았습니다. 보안 취약점과 강화 과제는 [보안 README](../security/README.md)에 기록했습니다.

## 기능 보존 기준

- OPT-001: 영역별 후보 정책, paired 문항 묶음, 개인 노출 횟수와 통계 의미를 유지합니다.
- OPT-002: 작업 상태 반영과 편집 상태를 보존하고, 화면 전환·언마운트·숨긴 탭의 요청 정리를 확인합니다.
- OPT-003: 직접 URL 접근, 로딩·오류 화면, 관리자 로그인과 각 탭 전환을 확인합니다.
- OPT-004: 작은 화면과 고해상도 화면의 선명도, 이미지 비율과 레이아웃을 확인합니다.
- OPT-005: 점수·미응답·만료 처리와 ON CONFLICT 기반 중복 제출 방지를 유지합니다.
- OPT-006: 연결 반납 후에도 소유권 검사 결과와 미디어 참조의 유효성이 유지되도록 경쟁 조건을 검토합니다.
- OPT-007: 취소·실패의 상태와 lease 회수, 제한된 재시도 및 finally 정리를 확인합니다.
- OPT-008: 키보드 조작, aria 상태와 펼침 애니메이션을 유지합니다.

1. OPT/OPS ID를 유지하고 상태를 `미수정 → 진행 중 → 수정됨·검증 대기 → 완료`로 갱신합니다.
2. 개선 전후에 같은 데이터·동시성·환경·빌드 조건을 사용하고 측정 날짜와 수치를 남깁니다.
3. 소스 분석의 예상 효과와 실측 효과를 구분합니다. 측정하지 않은 개선율은 기록하지 않습니다.

6. 이 폴더의 자료는 Git으로 공유·백업되지 않으므로 필요한 경우 별도 로컬 백업을 사용합니다.
